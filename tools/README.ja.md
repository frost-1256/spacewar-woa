# ツール

## dscprobe/

**DscProbe** のソース。稼働中セッションでグラフィックスドライバの 表示／DSC 状態を調べるための読み取り専用カーネルプローブ。 [dscprobe/README.ja.md](dscprobe/README.ja.md) を参照。

## phone/

電話側（`C:\`）に置いて管理者として実行する補助スクリプト：

| ファイル | 用途 |
|---|---|
| `gpu_now.bat` / `gpu_now.ps1` | GPU デバイスを手動で有効化し、状態を `C:\gpu_now.log` へ 5 分間ポーリング記録する。**後片付けはしない** — テスト後は自分で無効化し、再起動前に `ConfigFlags` が 1 に戻っていることを確認すること（[../STATUS.ja.md](../STATUS.ja.md) 参照）。 |
| `kd_on.bat` | カーネルデバッグを有効化（`bcdedit /debug on`）。WinDbg／KDNET セッション用。 |
| `kd_off.bat` | カーネルデバッグを無効化（既定）。オンのままホストが居ないと、ブートが KD トランスポート待ちで止まる。 |


## 採取の流れと後片付け

GPU 有効化前に[既知の問題](../docs/known-issues.ja.md)を読む。BAT は昇格して電話ルートの PowerShell を呼ぶ前提なので、gpu_now の2ファイルを一緒に配置する。10秒間隔30回の状態記録を行うが、MMIO 採取や DscProbe の代わりにはならない。通常ドライバが表示を給電・クロック有効にしている間に、プローブを別に実行する。

採取後は graphics を無効化し、ConfigFlags を照会して再起動前に1を確認する。後片付け前に凍結したら、ガジェットモードから電話の SYSTEM ハイブをオフラインで確認・修復する。読み取り専用でもプロセッサ間ランデブーは防げず、5分間のログは安定性認証ではない。

ログ、署名 SYS、中間成果物、証明書はリポジトリ外に置く。所有者識別情報を除かずに生ログを投稿しない。カーネルデバッグスクリプトは電話の BCD を変更するが、デバッガ接続の作成・設定はしない。
